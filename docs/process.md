## Изменения (CR)

1. Запрос с формулировкой «что / зачем / кто».
2. Оценка влияния на UC, срок и копии данных.
3. Решение: принять / отложить / отклонить.
4. Реализация в отдельной ветке, проверка pytest, ревью не автором.
5. В `main` только после зелёного CI.

Репозиторий: GitHub. Запрос на слияние не принимает его автор.

## Качество

- pytest на каждый merge: вход, права, поставки, статусы, копии.
- Негатив: чужая роль, блокировка, чужой файл, повторное принятие предложения.
- Перед M5 — полная регрессия и восстановление из копии.
- Дефект: критический / значительный / незначительный. Закрывает проверяющий, не автор.

## Внедрение и откат

Остановить запись, снять копию БД и файлов, применить `alembic upgrade head`, выложить релиз, прогнать UC-01–UC-12. Откат: предыдущий пакет + `scripts/restore.py` согласованной даты.

RPO ≤ 24 ч, RTO ≤ 4 ч. Дневные копии хранятся 7 дней, планировщик в API и/или cron `deploy/crontab.example`.

## HTTPS

`python scripts/make_certs.py` затем `python scripts/run_https.py` (порт 8443) либо `docker compose --profile https up`. Браузер предупредит о самоподписанном сертификате — для учебного пилота это допустимо.
